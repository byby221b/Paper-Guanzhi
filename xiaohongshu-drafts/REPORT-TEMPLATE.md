# 论文精读报告模板

> 此模板用于在撰写小红书分享之前，对论文进行系统性的深度阅读。
> 报告供作者自读，不对外发布，要求全面、严谨、不回避难点。
> 保存位置：xiaohongshu-drafts/reports/{期号}-{论文简称}-report.md

---

## 报告结构

### 一、论文元信息

```markdown
## 元信息

- 标题：{英文原标题}
- 作者：{全部作者，含机构}
- 发表：{期刊/会议, 年份}
- 原文链接：{URL}
- 精读日期：{YYYY-MM-DD}
- 对应小红书期号：#{XX}
```

### 二、作者背景

对每位主要作者进行简要考据：
- 学术身份（发表时的机构、职位、博士导师）
- 此前的代表性工作
- 此后的学术轨迹（是否获得重要奖项、创立了什么方向）
- 合著者之间的关系（师生、同事、合作背景）

```markdown
## 作者背景

### {作者1}
- 发表时身份：{机构, 职位}
- 师承：{博士导师 / 学术渊源}
- 此前工作：{与本文相关的前置研究}
- 后续轨迹：{后来的重要成就}

### {作者2}
...
```

### 三、历史语境

将论文置于其发表时的学术脉络中：
- 当时该领域的主流方法是什么？
- 有哪些未解决的核心问题？
- 同时期有哪些竞争性/互补性的工作？
- 本文的直接前驱是什么？（引用的关键文献）

```markdown
## 历史语境

### 当时的学术主流
{描述}

### 待解决的核心问题
{描述}

### 同时期的相关工作
{列举，注明关系：竞争/互补/平行}

### 直接前驱
{本文最重要的 3-5 篇引用文献，说明继承关系}
```

### 四、问题形式化

用准确的数学/形式化语言描述论文要解决的问题：
- 输入是什么？输出是什么？
- 形式化定义（如适用）
- 评价标准 / 目标函数

```markdown
## 问题形式化

### 问题定义
{用数学符号精确表述}

### 输入与输出
- 输入：{描述}
- 输出：{描述}

### 目标 / 评价准则
{描述}
```

### 五、核心方法

逐步拆解论文提出的方法，包括：
- 核心思想的直觉解释
- 形式化描述（算法伪代码 / 模型架构 / 数学推导）
- 关键定理及其证明思路（不必逐行推导，但要把握证明的骨架）
- 与前人方法的本质区别

```markdown
## 核心方法

### 直觉
{用 3-5 句话概括核心 insight}

### 形式化描述
{算法伪代码 / 模型定义 / 关键公式}

### 关键定理与证明
{定理陈述 + 证明思路概要}

### 与前人方法的本质区别
{对比表或文字分析}
```

### 六、关键公式推导

选取论文中最核心的 1-3 个公式/定理，
进行**逐步推导**，标注每一步的依据。
如果论文省略了推导步骤，需自行补全。

```markdown
## 关键公式推导

### 公式 1：{名称}

**原文表述：**
{原始公式}

**逐步推导：**
Step 1: {推导步骤} — 依据：{引理/假设/定义}
Step 2: {推导步骤} — 依据：...
...

**直觉理解：**
{用非形式化语言解释这个公式在"说什么"}
```

### 七、实验分析

如果论文包含实验部分（早期理论文章可能没有）：
- 实验设置（数据集、基线、评价指标）
- 主要实验结果及解读
- 消融实验（如有）
- 实验中的关键发现或意外结果
- 实验设计的优点与不足

```markdown
## 实验分析

### 实验设置
- 数据集：{描述}
- 基线方法：{列举}
- 评价指标：{列举}

### 主要结果
{表格或文字描述，附自己的解读}

### 消融实验
{如有}

### 关键发现
{超出预期的实验现象}

### 实验设计评价
- 优点：{描述}
- 不足：{描述}
```

### 八、论文的局限性

客观分析论文的不足，包括：
- 作者自己承认的局限
- 后来被指出的问题
- 假设的合理性
- 方法的适用范围

```markdown
## 局限性

### 作者自述
{论文中提到的局限}

### 后续批评
{后来的研究指出的问题}

### 假设检验
{论文的关键假设是否合理？在什么条件下不成立？}
```

### 九、后续影响

追溯这篇论文发表后的学术脉络：
- 直接后继工作（引用本文的重要论文）
- 开创了哪个子领域
- 对当代技术的影响
- 引用数据

```markdown
## 后续影响

### 直接后继
{最重要的 3-5 篇后续工作}

### 开创的方向
{描述}

### 当代回响
{在今天的技术栈中，这篇论文的思想体现在哪里？}

### 引用统计
- Google Scholar 引用数：{数字}（截至 {日期}）
- Semantic Scholar 引用数：{数字}
```

### 十、个人笔记

自由记录阅读过程中的思考：
- 最让我惊叹的 insight 是什么？
- 有没有什么地方我没完全理解？
- 这篇论文的写作有什么值得学习的？
- 如果我在当时，我会如何看待这个工作？

```markdown
## 个人笔记

{自由书写}
```

### 十一、小红书写作备忘

为后续撰写小红书帖子准备素材：
- 最适合作为 Hook 的故事/反差/事实
- 最适合向读者传达的 1 个核心 insight
- 最容易出错的知识点（自查重点）
- 推荐的动态 Hashtags

```markdown
## 小红书写作备忘

### Hook 素材
{列举 2-3 个候选 Hook}

### 核心 Insight（一句话）
{必须传达给读者的一个核心思想}

### 自查重点
{最容易写错的 2-3 个知识点}

### 动态 Hashtags
{建议的 2-3 个主题标签}
```

## 报告规范

- 语言：中文为主，术语保留英文原文
- 公式：使用 LaTeX 语法（$...$）
- 篇幅：不限，以读通读透为准，通常 3000–8000 字
- 引用：注明来源，格式 [作者, 年份] 或脚注
- 质量标准：报告完成后，应能回答以下问题：
  1. 这篇论文解决了什么问题？为什么这个问题重要？
  2. 核心方法是什么？关键公式/定理能否自行推导？
  3. 实验证明了什么？有没有没证明的声称？
  4. 论文的核心假设是什么？在什么条件下失效？
  5. 这篇论文对后世最大的影响是什么？
